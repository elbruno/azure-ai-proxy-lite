Events¶

Once you have configured the resources, you can use the same resources for multiple events. This guide will walk you through the process of setting up events.

TL;DR¶

  1. In the admin portal, open Events and add a new event.
  2. Enter the event name, Markdown description, organizer, start/end time, and time zone.
  3. Enable Active and select one or more Event Resources.
  4. Set Max Token Cap and Daily Request Cap. For a Copilot App event, start with a 4096 output token cap and validate Azure TPM/RPM using the capacity guide.
  5. Normally leave Event Shared Code blank. Set an alphanumeric code of at least five characters only when attendees need the no-GitHub access path.
  6. Save, open the event, select the Attendee/People icon, and copy the attendee URL.

Success: the attendee URL shows the event details during its active time window and offers registration or the organizer-provided shared-code instructions.

Before you start¶

At least one active resource must exist. Decide the event time zone, expected attendance, client profile, Azure model capacity, per-request token cap, and daily request cap.

Setting up events¶

From the AI Proxy Admin portal, you can create and manage events. An event is a time bound access to the AI Proxy service.

  1. Sign into the AI Proxy Admin portal (see Authenticating with the AI Proxy Admin).

  2. Select the Events tab, then add a new event.

  3. Add the event details, including the event name, start and end date.

  4. Event Name: The name of the event.

  5. Event Resources: You can select multiple resources for an event. The resources are the model and indexes that you configured in Resources.
  6. Organizer Name: The name of the event organizer.
  7. Organizer Email: The email of the event organizer.
  8. Start Date: The start date/time of the event. You can set the date/time using the date picker or by typing the date/time in the format YYYY-MM-DDTHH:MM:SS.
  9. End Date: The end date/time of the event. You can set the date/time using the date picker or by typing the date/time in the format YYYY-MM-DDTHH:MM:SS.
  10. Max Token Cap: The maximum output tokens allowed for one request. Use a value appropriate for the client and workload. The tested GitHub Copilot App profile uses 4096. See Capacity planning.
  11. Daily Request Cap: The maximum number of requests that can be made by a user to the Azure OpenAI resources per day. The goal of the Daily Request Cap is to prevent runaway usage and abuse of the model. The Daily Request Cap resets at midnight UTC.
  12. Description: The Markdown description of the event. This description is displayed when an event attendee registers for a time bound API Key to access the AI Proxy service.
  13. Select Save to create the event.

  14. Event Shared Code: In most cases, you can leave this field blank.

    • The Event Shared Code is used where attendees may not have a GitHub account or are unable to authenticate with one. Use it only for short workshops; GitHub registration is the normal path for longer events.

    • The API KEY authentication format is event-id@shared-code/email-address. For example, if the Event Shared Code is BUILD2024, and the event-id is 1111-1111, then the API Key for the event will be 1111-1111@BUILD2024/attendee@mail.com.

    • The event-id is a unique identifier for and event, its generated by the system and can be found in the URL of the event ATTENDEE page.

    • Note, no PII is stored, the API KEY is one way hashed (sha256) and stored in the database for per user usage tracking.

Verify¶

Open the attendee URL in a private browser window. Confirm the event name, local start/end times, description, and registration guidance are correct. Complete one test registration and make one request before sharing the URL broadly.

Troubleshooting¶

Symptom Fix
Event says it has not started or has ended Check start/end values and the selected event time zone.
Resource is missing from Event Resources Confirm the resource is active in the Resources page.
Attendee request is rejected for token size Increase the event Max Token Cap if the workload is legitimate, then retest capacity.
Attendees are rate limited Scale Azure model TPM/RPM; increasing the event cap does not increase Azure quota.
Shared-code key is rejected Confirm the format is event-id@shared-code/email-address and the code is at least five alphanumeric characters.
